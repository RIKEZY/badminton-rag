# 已否决的方案（保留作为决策记录）

这个目录放的是**试过但没有采用**的实现。留着不是为了用，是为了说明「为什么没采用」——
每个方案都跑过对照实验，结论有数据支撑。

## V2 方案：拆需求 → 分别检索 → 合并

**思路**：把一个复合问题拆成多个子问题（「球拍和羽毛球的规格分别是什么」→ 拆成两问），
分别检索，再合并上下文。动机是「一次检索只能命中一个主题，复合问题会漏掉一半」。

**代码**：

| 文件 | 作用 |
|:---|:---|
| `v2_planner.py` | 调 LLM 把问题拆成 N 个子问题 |
| `v2_retrieve.py` | 每个子问题独立检索，结果合并去重 |
| `v2_expand_test.py` | 单题效果对比 |
| `v2_group_test.py` | 8 题对照实验 |
| `v2_regression.py` | 回归检查（确认没有把原有能力搞坏） |

**为什么否决**：

单题有效——「球拍 + 羽毛球规格」从只答一半变成答全。但扩到 8 题对照，
**收益归零**：82 块语料下，v1 的单次检索本来就能覆盖问题涉及的多个主题。

根因是**病灶不存在**：v2 假设「一次检索只能命中一个主题」，但 top5 本来就有 5 个名额，
复合问题的两个主题各占 2–3 块，不需要拆。

**这个结论直接改变了后续方向**：瓶颈不在检索策略，在语料规模。
于是转向扩语料（82 → 649 块），扩完之后「同一概念多文档」的问题才真正暴露，
才需要 cross-encoder 重排。

## 切块粒度对照实验（未完成）

`切块粒度实验.md`

**思路**：重叠固定 100 字符，只改 `CHUNK_SIZE`（200 vs 500），看哪种更适合规则类语料。

**为什么没跑完**：跑 size=200 时发现，问题不在「块多大」，在「块怎么切」。
固定长度把 Law 9（发球规则）切成 20 多块，每段都不完整，命中哪一段都答不全。

**结果**：转向结构感知切块（按条款编号切 + 父级合并），这个对照实验就失去意义了——
不是 size 选得不对，是切法不对。

## 复现方式

这些脚本依赖项目根的模块，已各自加了 `sys.path` 修复，可以直接跑：

```
.venv/Scripts/python.exe experiments/v2_group_test.py
```

注意：会调 LLM API，有费用。
