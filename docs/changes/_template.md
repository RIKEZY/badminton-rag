# 变更记录模板

> 本目录只放**单次改动的证据**：改了什么、怎么验、原始输出在哪、怎么退。
> 决策理由不写在这里，写 `docs/项目技术手册.md`。两者不要互相抄。

---

## <YYYY-MM-DD> <一句话标题>

**编号**：<日期>-<slug>
**状态**：已采纳 / 已回滚 / 待确认

### 范围

| 文件 | 角色 |
|:---|:---|
| `path/to/file.py` | 被测代码 |
| `tests/test_x.py` | 规格测试 |

### 改动

一两句话说清行为变化。不要贴整段 diff，贴要点。

### 锚点

当前流程默认不 commit，因此不用 commit hash 作锚点。用**文件内容哈希**，与 git 历史无关，改一个字节就变。

| 文件 | blob hash |
|:---|:---|
| `path/to/file.py` | `<git hash-object 输出>` |

复核命令：

```bash
git hash-object path/to/file.py     # 应等于上表
git diff -- path/to/file.py          # 看具体改动
```

> 注意：worktree 里常有其他未提交改动，所以**不做全仓 diff 锚点**，只按文件锚定。

### 验收 gate

gate 必须先定义、再执行，不允许事后改判据。

| 项 | 内容 |
|:---|:---|
| 命令 | `<完整命令>` |
| 配置 | 例如 `RAG_RERANK=true`，重排开/关必须写明 |
| 数据集 | 10 题（有 ground truth）/ 80 题（非零结果率） |
| 判据 | 通过条件，写具体数字或集合关系 |
| 不适用 | 这条 gate 覆盖不到什么（写清楚边界，防止被过度引用） |

### 证据

原始输出文件，带时间戳，不手抄数字。

| 文件 | 内容 |
|:---|:---|
| `docs/eval-xxx.txt` | <命令、配置、题数、结果> |

### 结果

实测数值。写事实，不写评价。

### 裁决

**这一栏必须写。** 三种情况之一：

- 按 gate 判定通过。
- gate 未通过，但判定通过 —— 必须写清为什么 gate 在这里不适用、以及接受的风险。
- 判定不通过，回滚。

gate 未通过却判定通过时，没有这一栏，三个月后会被读成"带病上线"。

### 遗留

本轮没做、但必须做的事。写清楚为什么留到下一轮。

### 回滚

具体到能直接执行的动作，不要写"还原改动"。

```bash
# 例：git checkout -- path/to/file.py，或反向 patch 的具体内容
```

回滚后要重跑哪条 gate，一并写上。
